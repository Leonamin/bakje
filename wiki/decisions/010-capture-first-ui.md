# 010. 수집 우선 UI와 장식 제거

## Context

첫 모바일 UI를 실제로 써 보니 다음 문제가 나왔다.

- 수집 화면으로 가기가 어렵다. 수집이 하단 탭 오른쪽 끝에 있고, 붙여넣기 버튼이 11.5px 텍스트 버튼이라 잘 보이지 않는다. 저장까지 탭이 여러 번 필요하다.
- 글자가 작다. 9–10.5px 라벨이 곳곳에 있고, 라벨 대부분이 모노 대문자다. Pretendard는 이름만 지정되고 실제로 로드되지 않아 시스템 폰트로 보였다.
- 꼭 필요하지 않은 정보가 많다. 통계 줄, 영문 머리글, 수집 규칙·검색 팁 박스, 파서 버전, "미디어 N · 파트 N" 등이다.
- 상세에서 이어쓰기의 "원문 ↗" 링크가 10.5px 모노 텍스트라 거의 보이지 않는다. 본문과 이어쓰기의 경계도 흐리다.
- 모바일 이미지 뷰어가 확대 버튼·썸네일 줄·안내 문구로 조밀해서 정작 이미지가 작다.
- 검색 결과 썸네일이 64px 정사각형이라 내용과 함께 줄어든다.

웹에서는 화면 진입만으로 클립보드를 읽을 수 없다는 제약도 확인했다. 사용자 탭이 필요하고, iOS는 탭 후에도 확인 말풍선을 한 번 더 띄운다.

## Decision

- **수집을 메인 동선으로 올린다.** 하단 탭을 라이브러리 · 수집 · 검색 순으로 바꾸고, 수집을 가운데 원형 버튼으로 띄운다. 수집을 첫 화면으로 만들지는 않았다. 다시 읽으러 들어올 때 한 단계가 늘어나기 때문이다.
- **붙여넣고 저장을 버튼 하나로 만든다.** 탭 한 번에 클립보드 읽기와 제출을 함께 한다. 붙여넣기 / 저장 두 버튼을 나란히 두면 탭이 두 번 필요하다. 직접 입력은 보조 버튼과 시트로 둔다. 두 버튼 모두 엄지가 닿는 하단에 고정한다.
- **지원하지 않는 링크는 서버 입구에서 거절한다.** 실패 작업으로 쌓이지 않게 하고, 수집 화면과 앞으로 붙일 iOS 단축어 양쪽을 한 번에 막는다.
- **터미널풍 장식을 걷어낸다.** 모노 라벨, 격자 배경, 영문 머리글, 1px 괘선 위주의 구획을 버리고 둥근 판과 여백으로 구획한다. 팔레트([결정 008](./008-colorhunt-palette.md))와 Goodcase 컴포넌트([결정 007](./007-goodcase-ui-bridge.md))는 유지한다.
- **타입 스케일을 11 · 12 · 14 · 16 · 20 · 24px로 고정한다.** UI 기본은 14px, 게시글 본문은 16px이다. 사용자는 14px을 본문 기준으로 제안했지만, 14px은 앱 UI 기준이고 긴 글은 16px 이상이 일반적이라 본문만 16px으로 나눴다.
- **Pretendard Variable을 직접 서빙한다.** `next/font/local`로 woff2 파일 하나를 쓴다. npm `pretendard` 패키지는 node_modules에 98MB가 늘어 Docker 빌드가 무거워져서 쓰지 않았다.
- **상세 화면의 액션을 하단으로 내린다.** 모바일에서는 탭 바 대신 액션 바(번역/원문 · 정리 · 원문 열기)를 두고, 파트 인덱스 바와 파트 카드, 긴 파트 접기를 추가한다.

Before/After 시안을 먼저 만들어 방향을 합의한 뒤 구현했다.

## Consequences

- 수집이 탭 한 번(앱 진입 → 가운데 버튼 → 붙여넣고 저장)으로 줄었다. iOS 확인 말풍선 한 번은 플랫폼 제약이라 남는다.
- 폰트 파일 2MB를 첫 방문에 내려받는다. 모바일 데이터에서 느리면 dynamic subset으로 바꾼다.
- 상세 화면에서 하단 탭이 사라지므로 다른 탭으로 가려면 뒤로가기를 거쳐야 한다. iOS에서는 스와이프 뒤로가기로 처리된다.
- 데스크톱 정리 열의 패널에 저장 버튼이 없어 태그·메모가 저장되지 않던 기존 버그를 함께 고쳤다.
- 후속 과제:
  - iOS 단축어로 공유 시트에서 바로 수집하는 경로. 서버 거절 규칙은 이미 준비되어 있다.
  - 이미지 뷰어 아래로 쓸어내려 닫기
  - 토스트 stack의 표시 순서(새 알림이 이전 알림 뒤에 숨는 문제)

## Status

Accepted
