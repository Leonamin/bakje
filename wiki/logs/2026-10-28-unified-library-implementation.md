# 통합 라이브러리 구현

사용자와 논의한 기준을 구현했다. 출처는 X·Threads·Reddit·OpenNana 등의 원출처, 저장소는 실제 파일 위치, 컬렉션은 사용자 분류다. 연결 원본을 먼저 재배치할 필요 없이 박제가 자료 묶음과 작업 상태를 보유한다.

- 기존 SNS 상세 ID와 API를 보존하면서 공통 목록·검색에 연결했다.
- 연결 자료의 프롬프트·이미지·영상 역할과 순서, 묶음 기준, 원본 경로, 수정 버전을 기록한다.
- AI가 폴더를 조사하고 명시적인 자료 관계를 제출할 MCP 도구, OpenNana·파일 매니페스트 연결기를 추가했다.
- 등록·내보내기 커서와 레코드별 오류, 임베딩 입력·모델 버전·재시도·실행 임대를 DB에 보존한다. 사용자 관계 수정은 재스캔이 덮어쓰지 않는다.
- 검색 요청과 신규 자료 분석을 우선하고 대량 처리에도 실행 기회를 준다. 긴 텍스트는 작은 처리 차례로 나눠 캐시를 재사용한다.
- 원본을 유지하는 규격 사본 내보내기, TAR 다운로드와 재등록을 제공한다. 원본 위치에서의 파일 이동·이름 변경은 미구현이다.
- 미디어 정리가 연결 자료의 참조도 보존하도록 수정했다.

실제 OpenNana를 읽어 임시 DB에 18,142건을 등록했다. 텍스트 35,729개, 이미지 20,465개, 영상 613개, 실패 0건이며 반복 스캔에서 자료 중복이 없었다. 문자열 안 U+2028·U+2029를 줄 경계로 잘못 해석한 문제와 짧은 한국어가 섞인 검색어의 trigram 한계를 수정했다. `fashion` 4,564건 일치·60건 조회의 로컬 키워드 검색은 SQL 최적화 후 약 54ms였다. 실제 모델 추론 성능 측정값은 아니다.

타입 검사·UI 검사·프로덕션 빌드와 임시 DB 통합 테스트를 수행했다. 모의 모델 응답을 지연한 상태에서도 SNS 저장이 먼저 완료됐으며, 임베딩 캐시·오래된 결과 차단·연결 해제·실패 재시도·규격 재등록·HTTP 범위 응답을 확인했다. 데스크톱·390px 모바일에서 목록·검색·상세·폴더 탐색·정지·컬렉션 수정/필터를 확인했고, 실제 HTTP MCP 등록·조회·중복 방지·내보내기 왕복도 통과했다. 상세 검증은 Concepts의 현재 문서에 기록한다.

운영 서비스·데이터·컨테이너·원본 연결 폴더는 변경하지 않았다. 전체 실모델 임베딩은 실행하지 않았다.
