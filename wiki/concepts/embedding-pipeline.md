# 임베딩 파이프라인

모델은 `embeddinggemma-2`(CPU 사이드카, → [결정 014](../decisions/014-semantic-search-embedder-sidecar.md))다. 벡터는 256차원으로 줄여 정규화하므로 내적이 코사인 유사도다. 텍스트와 이미지가 같은 공간에 있어서 텍스트 질의로 이미지를 찾는다. 검색은 모든 벡터와 코사인을 계산하는 브루트포스이고, 글 단위로 가장 높은 점수 하나만 쓴다. 하한은 0.7이다(`SEMANTIC_MIN`). 모델 키(`MODEL_KEY`)가 바뀌면 전체를 다시 임베딩한다.

## 텍스트

- 입력은 `제목 + 요약 + 본문`을 `\n\n`으로 이은 텍스트다.
- `chunkText`는 빈 줄 기준 문단을 1500자까지 모으고, 문단 하나가 1500자를 넘으면 1500자에서 그냥 자른다. 겹침과 문장 경계 처리는 없다.
- **2번째 이후 청크 앞에도 제목을 붙인다**(`withTitle`, 2026-11-02). 이전에는 제목이 첫 청크에만 있어 뒤쪽 청크가 글의 주제를 몰랐다. 연결 폴더 텍스트는 제목 접두를 쓰지 않는다.
- 청크 텍스트 해시를 `embedding_cache`에 저장해서 같은 청크는 다시 계산하지 않는다.

## 이미지·영상

- 이미지 1장당 벡터 1개다. 긴 변을 896px 이하로 줄여 임베딩하고, 사물·인물·배경으로 나누지 않는다. 어떤 면을 볼지는 검색어가 정한다.
- 영상은 포스터 벡터(`media_embedding`)에 더해 **키프레임 벡터**(`media_frame_embedding`, 프레임당 1KB)를 둔다(2026-11-02).
  - 간격은 `max(3초, 길이÷8)`, 영상당 최대 8장이고 영상 전체에 고르게 배치한다(`frameTimes`).
  - 프레임 이미지는 임시로 뽑아 임베딩한 뒤 버리고 디스크에 저장하지 않는다.
  - 박제 영상 길이는 중앙값 8초, p90 12.5초다.
  - 이미지 1장 임베딩은 CPU에서 약 2.2초다.
  - 연결 폴더 영상과 관련 항목(`related-items`)은 아직 프레임을 쓰지 않는다.
- 영상 포스터는 `ffmpeg`로 만든다. 이전에는 웹 컨테이너에 `ffmpeg`가 없어 영상 31건의 포스터와 이미지 벡터가 비어 있었다. → [미디어 파이프라인](./media-pipeline.md)

## 측정 (2026-11-02, 박제 이미지)

- 박제 글 75건 중 1500자를 넘는 글은 21건(28%)이고, 문단 하나가 1500자를 넘어 강제 절단이 생기는 글은 4건이다.
- 이미지 57건 기준 질의 16개를 직접 만들어 측정했다. 14개에서 정답이 1~2위였고 점수는 0.72~0.80이다. 질의를 이미지를 본 뒤에 만들었고 표본이 작아 낙관적일 수 있다.
- 도표·정리표·인포그래픽도 글자를 읽지 못해도 레이아웃으로 1위에 올랐다.
- 약한 곳: 이미지 속 글자 내용(일본어 오류 메시지 스크린샷 0.619로 하한 미달), 하한 0.7 바로 위의 경계 점수(워크플로 다이어그램 0.701).

## 연결 폴더 검색: 이미지와 텍스트 점수 합산 (2026-11-02, [#21](https://github.com/Leonamin/bakje/pull/21) 배포)

- OpenNana에서 "남자"를 검색하면 여자 사진이 더 많이 나왔다. 사진 쪽 문제가 아니었다. 이미지 점수 상위 32장은 94%가 남성 사진이다.
- 원인은 점수 합산이다. 연결 폴더 검색은 항목마다 이미지와 프롬프트 텍스트 벡터 중 **가장 높은 점수** 하나로 줄을 세운다. 긴 프롬프트는 짧은 질의와의 코사인이 이미지보다 높다. "남자" 기준 텍스트 최고 0.797, 이미지 최고 0.732다. 0.7 이상은 텍스트 613건, 이미지 64건이다.
- 그래서 상위 300개 후보 중 이미지 근거는 8개뿐이었고 상위 40건은 모두 텍스트 근거였다. 프롬프트가 대부분 여성 사진용이라 결과가 쏠렸다.
- 수정: 이미지와 텍스트를 각각 순위화한 뒤 RRF로 합친다. 운영 DB 복사본에서 같은 질의의 상위 40건 근거가 텍스트 40건에서 이미지 22건과 텍스트 18건으로 바뀌었다. 정량 평가는 "남자" 한 질의의 육안 비교다.
- 텍스트와 이미지 코사인은 서로 다른 눈금이므로 점수를 직접 비교하지 않고 순위로 합친다(하한 0.7은 양쪽에 그대로).
- 이미지 전용 순위로 봐도 "남자"는 상위 약 60위까지만 정확하다. 61~120위와 241~300위는 남녀가 약 절반씩 섞인다. 한 질의의 코사인 점수로는 성별 경계를 가르지 못한다.
- **`-단어`를 벡터 제외로 반영한다**([#24](https://github.com/Leonamin/bakje/pull/24), 2026-11-02). 질의 벡터에서 제외어 벡터를 빼고 정규화한다(`minus`). `남자 -여자`는 이미지 전용 101~160위와 241~300위도 거의 전부 남자 사진이었다. 새 UI 없이 기존 `-단어` 문법을 쓴다. 빼낸 벡터는 점수 눈금이 달라(약 0.07대) 0.7 하한 대신 순위로 상위 300을 정한다. 불리언 NOT이 아니라 방향 산술의 근사이며, 육안 비교만 했다. 제외어는 키워드 제외에도 쓰여 본문에 그 단어가 있는 항목은 빠진다.
- 이미지만 따로 검색하는 필터는 **추가하지 않았다.** 필터 패널이 이미 복잡하고, 기존 "형식: 이미지 포함"은 이미지를 가진 항목을 거를 뿐 이미지 내용 검색이 아니다. 배포 후 써 보고 텍스트가 계속 거슬리면 검색창 옆 토글 칩 하나(`by=image`, 키워드 검색을 건너뛰고 이미지 후보만 순위화)로 추가한다. 형식 Select 확장과 새 Select 추가는 쓰지 않는다.

## 보류한 개선 (현재 규모에서는 과하다고 판단)

- 재귀 분할·겹침, 이미지 속 글자 검색(VLM·OCR), 연결 폴더 영상 키프레임(613건, 약 75분 CPU), 관련 항목의 프레임 반영, 벡터 인덱스.
- 다시 검토할 때: 검색해도 안 나온다는 구체적 사례가 생기거나 긴 글·글자 위주 이미지가 크게 늘었을 때.
- 검토한 오픈소스: [LangChain 재귀 분할](https://python.langchain.com/docs/how_to/recursive_text_splitter), [semchunk](https://pypi.org/project/semchunk/), [Chonkie](https://github.com/chonkie-inc/chonkie), [jina late chunking](https://github.com/jina-ai/late-chunking), [Anthropic Contextual Retrieval](https://anthropic.com/news/contextual-retrieval), [Immich 스마트 검색](https://docs.immich.app/features/search). 벤치마크 수치는 각 프로젝트의 주장이며 직접 검증하지 않았다.
