# 미디어 파이프라인

## 원칙

미디어는 **반드시 로컬에 복제**한다. 핫링크면 원문 삭제 시 이미지도 같이 죽어서 제품 목적이 무너진다.

## 다운로드

- 스트리밍으로 받으면서 누적 바이트를 검사하고 **30MB를 넘으면 중단**한다(`too_large`).
- `content-length`가 이미 상한을 넘으면 본문을 읽지 않고 즉시 실패 처리한다.
- 성공하면 sha256으로 파일명을 정하고, 같은 해시가 있으면 파일을 다시 쓰지 않는다.
- 확장자는 content-type 우선, 없으면 URL에서 추론한다.

## 영상

- X: `video_info.variants`에서 **2.5Mbps 이하 중 가장 높은** bitrate mp4를 고른다(없으면 가장 낮은 것). Article 영상은 최고 화질이 10Mbps라 30MB를 거의 항상 넘기 때문이다. 영상 길이를 모르므로 비트레이트 상한으로 대신하는 임시 방법이다. Article의 변형은 키가 `bit_rate`(밑줄)다.
- X 다운로드는 `x.com` referer가 필요하다. `video.twimg.com`은 그 밖의 referer(예: 구글)에 403을 준다(`media.ts` `download()`). 이 수정 전에는 X 영상이 `failed`로 남았을 수 있다. 일반 X 영상 트윗에서의 재현은 **미검증**이다(로컬에 X 영상 기록이 없었다).
- Reddit: `shreddit-player`의 `src`가 **HLS 매니페스트**다. 세그먼트가 한 CMAF 파일의 바이트 범위라 파일 단위로 받아 ffmpeg으로 오디오와 합친다.
- Threads: `video_versions` 최대 해상도

이 환경의 정적 ffmpeg 빌드는 네트워크 입력에서 세그폴트가 난다. 그래서 **다운로드는 Node가 하고 ffmpeg은 로컬 mux·포스터 생성에만** 쓴다.

## 표시

`.media-tile`은 이미지·영상 모두 `object-fit: cover`였다. 영상 타일은 폭 100%·최대 높이 520px이라 세로 영상(9:16)의 위아래가 잘렸다. 영상만 `contain`으로 바꿨다(`globals.css`). 카드 썸네일(`img`)은 격자를 위해 계속 자른다.

## 포스터

영상·gif에서 0.5초 지점 프레임을 720px로 뽑는다. 아주 짧은 클립은 0.5초에 프레임이 없으므로 첫 프레임으로 재시도한다. 포스터가 없으면 목록 썸네일이 깨지므로 `npm run gc`가 누락된 포스터를 복구한다.

## 카드 썸네일

- 라이브러리·검색 카드는 원본이 아니라 `/api/media/<파일>?w=320|640|960`을 쓴다(목록 320, 격자 640, 검색 피드 960). 원본은 운영 기준 중간값 약 227KB라 이미지가 많은 화면에서 모바일 회선 로드 실패가 났다.
- 미디어 라우트가 sharp로 첫 요청 때 webp(품질 78, 확대 없음)를 만들고 `DATA_DIR/thumbs/<폭>/`에 저장한다. 이후는 파일을 그대로 보내며 `immutable` 캐시다. 파일 이름이 해시라 무효화가 필요 없다.
- 허용 폭 이외 값, GIF, 디코딩 실패는 원본을 그대로 보낸다. 상세 화면과 이미지 뷰어는 원본이다.
- 썸네일 디렉터리는 `media/` 밖이라 `gc`가 건드리지 않는다. 지워도 다음 요청에 다시 만들어진다.
- 서버 부하는 원인이 아니었다: 운영 서버에 이미지 210건 동시 요청이 실패 0건이었다. 실기기에서 실패가 줄었는지는 **미검증**이다.

## 정리

`npm run gc`:
- `media`/`media_blob`이 참조하지 않는 파일 삭제
- 중단된 다운로드의 `.tmp-*` 삭제
- 포스터가 없거나 사라진 영상·gif의 포스터 재생성

## 저장 공간 표시

설정 화면에 박제가 쓰는 용량을 폴더별(미디어, 원본 HTML, DB, 썸네일, 브라우저 프로필)로 보이고, 디스크 여유와 전체 용량을 함께 보인다(`storageUsage()` in `db.ts`, 요청 때마다 디렉터리를 순회). 폴더가 없으면 0으로 센다. 파일이 아주 많아졌을 때의 응답 시간은 **미검증**이다.

## 알려진 한계

- 30MB 상한은 영상 길이 기준이 아니라 파일 크기 기준이다. 고화질 짧은 영상은 저장되고, 긴 저화질 영상은 제외될 수 있다.
- HLS가 단일 파일이 아닌 다중 세그먼트로 오는 경우를 위한 연결 경로가 있으나, 실제로 그런 플랫폼을 만나 검증하지는 않았다.
- Reddit 영상은 오디오 트랙이 별도 파일이라 mux가 실패하면 무음 영상이 남는다.
