# 통합 라이브러리

## 자료를 분류하는 기준

출처, 저장 위치, 컬렉션을 별도로 관리한다.

| 기준 | 의미 | 예 |
|---|---|---|
| 출처 `origin` | 자료가 나온 곳 | X, Threads, Reddit, OpenNana, local |
| 저장소 `storage_id` | 실제 파일이 있는 위치 | 박제 기본 저장소, NAS, 프로젝트 폴더 |
| 컬렉션 | 사용자의 분류 | 패션 참고, 실험 기록 |

X 자료가 연결 폴더에 저장될 수도 있고, SNS 자료와 폴더 자료가 같은 컬렉션에 속할 수도 있다. 폴더 연결을 X·Threads·Reddit 중 하나로 가장하지 않는다.

자료는 검색 결과의 한 건이다. 구성요소에는 역할과 순서가 있다. 한 자료에 언어별 프롬프트, 참고 이미지 여러 장, 결과 이미지 여러 장, 영상 여러 개를 연결할 수 있다. 파일 개수는 1:1로 제한하지 않는다.

## 현재 구현

- `/`: SNS와 연결 자료의 공통 목록, 출처·저장소·컬렉션·미디어 필터, 페이지 이동.
- `/items/[id]`: 연결 자료의 프롬프트·이미지·영상·원본 경로·묶음 기준과 수정 버전. **자료 묶음 편집**에서 역할·언어·순서 변경, 분리·합치기와 최근 변경 되돌리기를 지원한다.
- `/sources/[id]`: 기존 SNS 상세 주소 유지. 컬렉션 분류 추가.
- `/library`: 폴더 연결·연결 해제, 폴더 탐색, OpenNana 등록·수동 새로고침, 매니페스트 등록, 작업 상태·실패 내역·재시도, 대량 분석 일시 정지.
- 저장소별 수동·매시간·매일 스캔 선택. 자동 스캔은 이전 OpenNana 또는 파일 매니페스트 규칙을 재사용한다. AI의 판단을 주기적으로 다시 추측하지 않는다.
- 원본 폴더 정리: 상세에서는 한 자료, `/library` 저장소에서는 전체 자료의 계획을 작성하고 선택해서 적용·되돌린다. [묶음 편집과 원본 정리](./library-organization.md) 참조.
- 박제 규격의 사본 내보내기와 TAR 다운로드, 내보낸 `items.jsonl` 또는 개별 `item.json` 재등록.

기존 수집 API와 SNS 검색 API는 호환성을 위해 유지한다. 전체 자료 API는 `/api/library?search=1&q=...`와 MCP `search_library`다.

## 선택, 휴지통과 셔플

- 모바일에서 자료를 550ms 길게 누르거나 PC의 **선택** 버튼으로 선택 모드에 들어간다. 전체 선택은 현재 페이지 범위다. 선택한 자료를 숨기거나 휴지통으로 이동하고, 숨긴 자료에서는 숨김을 해제하며 휴지통에서는 삭제를 취소한다.
- 휴지통 이동 시 `library_item.deleted_at`에 시각을 기록한다. 일반 목록·검색에서는 제외하고, 휴지통에서만 표시한다. 삭제 취소는 이 시각만 지우므로 이전 숨김 상태가 유지된다. SNS 삭제 API도 휴지통으로 이동한다.
- 서버 시작 시와 매시간 7일이 지난 항목을 정리한다. 서버가 중지됐거나 저장소가 원본 정리 작업으로 잠겨 있으면 처리가 늦어질 수 있다. 관련 묶음 변경과 원본 정리 계획은 실제 삭제 시 되돌리기가 비활성화된다.
- 연결 폴더의 원본은 삭제하지 않는다. 삭제된 자료의 저장소와 외부 ID를 tombstone으로 남겨 재가져오기에서 재등록을 막는다. SNS 미디어는 삭제 후보로 기록한 뒤 참조되지 않는 파일만 정리한다. 원본 HTML 스냅샷은 자동 정리 범위에 없다.
- 라이브러리와 별도 검색 화면에서 셔플할 수 있다. URL의 시드와 자료 ID로 순서를 정하므로 페이지 이동 시 시드가 유지된다. 다시 섞으면 시드가 바뀐다.
- 검증: `pnpm test:trash`는 삭제·복구·만료, 관련 이력 무효화, 공유 미디어 보존과 미참조 파일 정리를 임시 DB로 확인한다. 모바일 선택은 합성 터치 이벤트로 확인했으며 실기기 검증은 하지 않았다.

## 연결과 데이터 소유권

연결·등록·계획 작성은 원본을 읽기만 한다. 등록은 파일 이동을 요구하지 않는다. 원본 폴더 정리는 쓰기 가능한 연결에서 사용자가 계획을 검토해 적용할 때만 파일을 이동한다. 운영 OpenNana 마운트는 읽기 전용을 유지한다. 자료 관계·컬렉션·메모·사용자 수정 여부는 박제 DB에 보존한다. 기본 저장소의 미디어 정리는 연결 파일에 접근하지 않는다.

저장 위치는 저장소 ID와 상대 경로로 기록한다. 파일 접근 시 실제 경로를 다시 확인해 루트 밖으로 나가는 상위 경로와 심볼릭 링크를 차단한다. 연결 해제는 검색 범위에서 제외할 뿐 자료나 원본을 삭제하지 않는다. 연결 장애나 실패한 스캔으로 자료를 삭제하지 않는다.

정상 스캔에서 사라진 레코드를 자동 삭제하는 기능은 없다. 파일 부재와 연결 장애의 상세 동기화 정책, 외부에서 이동한 파일의 자동 추적은 후속 범위다.

## AI 에이전트와 박제의 책임

AI는 사용자가 지정한 기준으로 폴더 구조와 내용을 해석한다. 박제는 그 결과를 검증하고 자료 등록·검색·분석·재시도를 수행한다.

```text
사용자: 프로젝트·버전별로 묶고 모델별 결과는 함께 보여줘
  → AI: 연결 폴더 조사, 본문·이미지 확인
  → AI: 안정적인 외부 ID, 구성요소 역할·순서, 판단 근거 작성
  → 박제: 등록 작업 접수, 파일 접근·규격 검사
  → 박제: 자료 등록과 분석 작업을 같은 트랜잭션에 기록
  → 박제: 텍스트 색인, 배경 임베딩, 진행 상황·오류 관리
```

관계가 불확실하면 `review_required: true`로 등록한다. 직접 수정한 자료는 `user_locked`로 보존한다. 자동 재등록은 해당 자료를 건너뛴다. 관계를 의도적으로 변경하려면 현재 `revision`을 읽고 `expected_revision`을 포함해 같은 `external_id`로 다시 제출한다. 버전이 다르면 갱신을 거절한다.

MCP 도구:

| 작업 | 도구 |
|---|---|
| 저장소 목록·연결 | `list_library_storages`, `connect_library_folder` |
| 폴더·본문·이미지 조사 | `browse_library_folder`, `read_library_text`, `inspect_library_image` |
| AI 해석 결과 등록 | `register_library_items` (요청당 1~100건) |
| 기존 대량 데이터 등록 | `import_opennana`, `import_library_manifest` |
| 작업 조회·제어 | `get_library_job`, `control_library_job`, `retry_library_analysis` |
| 전체 자료 조회·수정 | `search_library`, `get_library_item`, `edit_library_item` |
| 구성요소 편집·분리·합치기·복구 | `edit_library_components`, `split_library_item`, `merge_library_items`, `undo_library_structure` |
| 원본 정리 계획·조회·제어 | `plan_library_organization`, `get_library_organization`, `control_library_organization` |
| 규격 사본 생성 | `export_library_items` |

기존 MCP 토큰 인증을 사용한다. 폴더의 텍스트는 분석 대상 데이터이며 에이전트 실행 지침으로 취급하지 않는다.

## 등록 규격 v1

`external_id`는 연결 저장소 안에서 안정적이어야 한다. 제목이나 해시를 바꿨다는 이유로 ID를 바꾸지 않는다. 프롬프트 버전을 별도 자료로 관리하려면 외부 ID에 그 버전의 식별자를 넣는다.

```json
{
  "schema_version": 1,
  "external_id": "garden:v01",
  "title": "정원 패션 v01",
  "kind": "prompt",
  "origin": "local",
  "collections": ["패션 참고"],
  "metadata": {"previous_version": "garden:v00"},
  "components": [
    {"key": "prompt:en", "kind": "text", "role": "prompt", "language": "en", "path": "prompt.en.txt"},
    {"key": "reference:1", "kind": "image", "role": "reference", "path": "reference.jpg"},
    {"key": "result:1", "kind": "image", "role": "result", "path": "result.jpg"},
    {"key": "video:1", "kind": "video", "role": "result", "path": "result.mp4"}
  ]
}
```

MCP와 직접 JSON 제출의 경로는 저장소 루트 기준이다. 파일 매니페스트로 등록할 때 구성요소 경로는 그 매니페스트 파일의 부모 폴더 기준이다. `path_base: "storage"`를 명시한 매니페스트는 경로를 연결 저장소 루트 기준으로 해석한다. 이는 원본 정리 결과에서 여러 자료가 공유하는 파일을 한 번만 이동하기 위한 규격이다. 텍스트는 `path` 대신 `text`로 직접 전달할 수도 있다.

사본 내보내기는 `DATA_DIR/exports/<작업 ID>/<자료 ID>/`에 파일과 `item.json`을 생성하고, 작업 루트에 일괄 재등록용 `items.jsonl`을 생성한다. 원본은 이동하지 않는다. 원본 위치에서 이동·이름 변경하려면 별도의 원본 정리 계획을 만들고 적용한다. 사본 내보내기와 달리 이 작업은 원본 경로를 바꾼다.

## OpenNana 연결

`prompts.jsonl`과 `media/`가 있는 폴더를 연결한다. 레코드 ID로 자료를 식별하고 매니페스트 URL→파일 관계를 사용한다. 같은 URL이 여러 파일에 매핑되면 레코드 ID·순번에 맞는 파일을 우선한다. 이전 호스트의 절대 경로는 알려진 미디어 경로를 통해 연결 루트 기준으로 변환한다.

JSONL은 LF로만 레코드를 구분한다. 프롬프트 문자열 안의 U+2028·U+2029는 유효한 JSON 데이터이므로 줄 경계로 분리하지 않는다.

Docker는 폴더를 먼저 읽기 전용으로 마운트해야 한다. 예시 `compose.library.example.yml`은 기존 Compose의 서비스 설정을 유지하면서 호스트 폴더 하나를 컨테이너 `/library`에 추가한다. 웹에서는 `/library`를 등록한다. 운영에서는 `/etc/bakje/compose.override.yml`의 읽기 전용 마운트를 사용하고 웹에 `/library/opennana`를 등록한다. [운영과 배포](./operations.md)의 연결 폴더 절차를 참고한다.

## 저장과 분석 작업

원본 저장과 자료 등록이 완료되면 임베딩을 기다리지 않고 열람·키워드 검색할 수 있다.

- 등록·내보내기: `library_run`, `library_run_entry`에 커서·진행 수·레코드별 오류 기록. 프로세스 중단 후 임대 시간이 만료되면 재개한다.
- 분석: `analysis_job`에 대상·입력 해시·모델/전처리 버전·우선순위·시도 횟수·다음 시도 시각·실행 임대 기록.
- 검색어 임베딩을 대기 중인 배경 추론보다 우선한다. 실행 중인 추론은 끝난 뒤 다음 요청을 고른다.
- 새 SNS와 소량 직접 등록은 초기 대량 등록보다 우선한다. 여섯 번째 작업 차례에는 대량 처리에도 실행 기회를 준다.
- 긴 텍스트는 최대 1,500자 청크로 나누고 한 차례에서 새 청크 4개까지 계산한 뒤 다른 작업에 차례를 넘긴다. 완료 청크는 캐시에 남아 재개 시 재사용한다.
- 입력·처리 조건이 같은 텍스트/이미지 임베딩 재사용. 늦게 끝난 이전 버전은 현재 구성요소를 덮어쓰지 않는다.
- 오류는 최대 5회 재시도 후 실패 상태로 유지한다. 누락 파일을 영구 빈 벡터로 처리하지 않는다.
- 대량 분석 일시 정지는 신규 수집과 소량 자료 분석을 막지 않는다.
- 모델/전처리 구분 키는 `EMBED_INDEX_VERSION`이며 기본값은 현재 embeddinggemma-2, 256차원, 청크/이미지 처리 버전이다. 모델이나 전처리를 바꿀 때 새 키를 사용한다. 서로 다른 키의 벡터는 비교하지 않는다.

영상은 이 단계에서 파일 보관 위치·재생·관계·이름 검색을 지원한다. 연결 영상의 포스터 생성·전사·장면 임베딩은 후속 범위다. OCR·직접 업로드·외부 파일 이동 추적도 아직 구현하지 않았다.

## 검증

- `pnpm test:library-management`: 역할·순서, 분리·합치기·되돌리기, 버전 충돌, 임베딩 재사용, 읽기 전용 차단, 계획과 적용, 공유 파일, 규격 재등록, 되돌리기 충돌, 파일/DB 체크포인트 중단 및 양방향 부분 복사 복구, 심볼릭 링크 경로 제한 검증.

- `pnpm typecheck`, `pnpm lint:ui`, `pnpm build` 통과.
- `pnpm exec tsx scripts/test-library.ts`: 임시 파일·모의 모델 서버로 등록, 검색, 캐시, 이전 결과 차단, 수정 잠금, 경로 제한, 연결 해제, 부분 실패·재시도, 규격 내보내기·재등록, HTTP Range, 기존 SNS 호환성 확인. 추가로 이전 입력으로 되돌리기, 만료된 실행 임대 복구, 주기 스캔, 대량 정지 중 신규 우선 처리, 분석 지연 중 SNS 저장, 검색어 요청의 대기 시간 제한, 미디어 정리의 연결 참조 보존을 확인했다.
