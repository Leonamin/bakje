# iOS 단축어 수집

X·Threads·Reddit 앱의 공유 시트에서 단축어를 실행하면 링크가 곧바로 박제 서버로 간다. 앱을 열고 수집 탭에서 붙여넣기를 승인하는 단계가 없어진다. 접근은 지금처럼 tailnet으로 제한하고 인증은 붙이지 않았다. → [결정 001](../decisions/001-single-user-local.md)

## 서버 입력 (`/api/ingest`)

- 본문으로 JSON `{urls}`·`{url}`·`{text}`와 일반 텍스트를 모두 받는다. 공유된 글에 섞인 링크만 골라내고(`src/lib/canonical.ts`) 중복은 제거한다.
- 응답 JSON에 한국어 `message`를 붙인다: 박제를 시작했습니다 / 이미 저장된 게시글입니다 / 지원하지 않는 링크 N개 제외.
- `?format=text`면 메시지 한 줄을 일반 텍스트로, **항상 200**으로 돌려준다. 단축어가 4xx 응답 본문을 보여주는지 확인하지 못해서, 결과를 "알림 보기"에 그대로 띄우기 위해 이렇게 했다.
- 앱이 쓰는 JSON 응답(`jobs`, `rejected`, `error`, 상태 코드)은 바뀌지 않았다.
- 본문 해석 자체 검사: `npx tsx scripts/test-extract.ts`

## 도움말 페이지 (`/help/shortcut`)

- 수집 화면 제목 줄의 "공유 시트로 저장" 링크에서 들어간다. 다른 화면에서 가는 길은 아직 없다.
- 단축어 만드는 8단계와 "잘 안 될 때" 7항목. 수집 주소는 복사 칸(`src/components/copy-field.tsx`)으로 제공한다.
- 1~6단계는 iOS 27 실기기 캡처(`public/help/shortcut-*.webp`, 520px 폭, 원본 PNG는 저장소에 넣지 않았다)다. 7~8단계(앱에서 공유, 허용 창)는 단순화한 인라인 SVG다. 단계의 `capture`를 지정하면 그림 대신 캡처가 나온다.
- 단축어 이름은 캡처에 맞춰 "박제하기"로 안내한다.

## iOS 27 단축어에서 확인한 것

- 흐름: 모든 단축어의 `+` → "단축어로 어떤 동작을 실행하겠습니까?" 설명 입력창(Apple Intelligence) → 오른쪽 위 `편집` → 아래 검색 시트에서 동작 추가.
- **ⓘ(세부사항)는 동작을 하나 추가해야 도구 막대에 나타난다.** 검색 시트가 펼쳐져 있으면 막대가 가려진다. 세부사항의 `공유 시트에서 보기`를 켜면 맨 위에 "공유 시트에서 … 받기" 블록이 생긴다.
- 동작 이름: `URL 콘텐츠 가져오기`(`URL의 콘텐츠 가져오기`가 아니다), `알림 보기`, `입력에서 URL 가져오기`. 본문 요청 필드는 `새로운 필드 추가`로 줄을 만들고 **`키` 칸을 직접 채워야** 한다.
- 새 단축어의 "입력이 없는 경우" 기본값은 `계속하기`다.
- 실패 사례: `키`가 비면 서버가 링크를 못 찾아 "URL을 입력해주세요."를 돌려준다(`extractCandidates`는 `url`·`text`·`urls`만 읽는다). 단축어 앱 ▶로 직접 실행해도 입력이 없어 같은 메시지가 뜬다. 처음 안내가 "키에 url"이라고만 적고 키 칸이 비어 있는 캡처를 쓰면서 헷갈리게 했다.
- 실기기 검증: `url` 키를 채우면 공유 시트로 보낸 링크가 저장까지 된다(2026-10-25).

## 미검증

- 첫 실행 허용 창 문구, 권한 재설정 경로.
- 각 앱의 공유 메뉴 이름("더 보기", "다음으로 공유…").
- iCloud 단축어 공유 링크는 실제 iPhone에서 만들어야 해서 페이지에는 아직 없다는 안내만 있다.
