# UI 시스템

## 방향

개인용 도구에서 가장 자주 하는 일은 **수집**이고, 그다음이 **다시 읽기**다. 수집은 엄지 한 번으로 끝나야 하고, 읽는 화면에는 판단에 필요 없는 정보를 두지 않는다.

초기 버전의 "계기판·터미널" 장식(1px 괘선, 모노 대문자 라벨, 격자 배경, 영문 머리글)은 2026-10-25 개편에서 걷어냈다. 지금은 둥근 판(radius 16)과 여백으로 구획한다. 팔레트는 그대로 유지한다. → [결정 010](../decisions/010-capture-first-ui.md)

## 정보 구조

- 하단 탭 3개: 라이브러리 · **수집** · 검색. 높이는 64px + 안전 영역이고, 수집은 가운데에 띄운 56px 원형 버튼이다.
- 데스크톱(md 이상)은 상단 내비게이션으로 전환하고, 수집 항목을 강조색으로 표시한다.
- 주요 액션은 엄지가 닿는 화면 하단에 둔다. 토스트는 하단 버튼을 가리지 않도록 위에서 내려온다(`direction="down"`).
- 게시글 정리는 **하단 시트**다. 통합 라이브러리의 출처·저장 위치·컬렉션·형식·정렬·태그는 공용 Select로 선택하고 즉시 URL에 반영한다.
- 아이콘은 Lucide만 쓴다. 글자 기호(↗ × ‹ ›)나 이모지로 대신하지 않는다.

## 화면

| 경로 | 역할 |
|---|---|
| `/` | 라이브러리. 머리글 오른쪽에 새로고침 버튼. 검색창, 플랫폼·미디어 칩, 그리드(기본)/목록 보기 전환. 미디어 없는 글은 썸네일 자리까지 본문을 7줄 보여준다. |
| `/search` | 전용 검색. 결과 카드는 썸네일을 카드 폭에 꽉 찬 16:9로 보여주고, 썸네일이 없으면 본문 3줄을 보여준다. 검색어가 없을 때는 태그 칩만 둔다. |
| `/add` | 수집. 하단 고정 `[직접 입력] [붙여넣고 저장]`과 최근 작업 목록. |
| `/sources/[id]` | 읽기. 하단 액션 바, 파트 인덱스 바, 파트 카드, 번역 컨트롤, 이미지 뷰어, 정리 시트. |
| `/settings` | LLM 번역 설정, X 쿠키, 저장 공간 사용량. 라이브러리 머리글(모바일)·상단 바(데스크톱)의 톱니 아이콘. |
| `/help/shortcut` | iOS 단축어 만들기 안내. → [iOS 단축어 수집](./ios-shortcut.md) |

### 새로고침 버튼

홈 화면에 추가한 웹앱(`display: standalone`)에는 브라우저 새로고침이 없어서 라이브러리와 수집 머리글에 버튼을 뒀다(`src/components/refresh-button.tsx`). `window.location.reload()`로 전체를 다시 불러와 새 배포도 받는다. 당겨서 새로고침은 만들지 않았다. 목록 스크롤·시트와 제스처가 겹치고 발견하기 어려워서, 필요해지면 `scrollTop === 0`일 때만 동작하게 더한다. `globals.css`에 `overscroll-behavior-y: none`이 이미 걸려 있다.

### 수집 (`/add`)

- **붙여넣고 저장**: `navigator.clipboard.readText()`로 클립보드를 읽고, `http(s)://` 링크만 골라 바로 `/api/ingest`에 보낸다. 링크가 없으면 경고 토스트를, 클립보드를 읽지 못하면 직접 입력 시트를 연다.
- **공유 시트로 저장**: 제목 줄의 링크가 `/help/shortcut` 안내로 간다.
- **직접 입력**: 시트에서 여러 링크를 줄 단위로 받는다.
- 지원하지 않는 링크는 서버가 작업을 만들지 않고 거절한다. 일부만 거절되면 "지원하지 않는 링크 N개는 제외했습니다"를 알린다. → [플랫폼 어댑터](./platform-adapters.md)
- 서버에 닿지 못하면 링크를 브라우저 대기열에 넣고 목록 맨 위에 "전송 대기"로 보여준다. 재시도를 기다리는 작업은 시계 아이콘과 다음 시도 시각으로 표시한다. 서비스 워커 덕분에 오프라인에서도 이 화면이 열린다. → [수집 작업 큐](./capture-queue.md)
- 웹에서는 화면에 들어오는 것만으로 클립보드를 읽을 수 없다. 사용자의 탭이 필요하고, iOS는 탭 후에도 시스템 "붙여넣기" 확인 말풍선을 한 번 더 띄운다(실기기 미검증).

### 상세 (`/sources/[id]`)

- 모바일에서는 하단 탭 대신 **액션 바**를 둔다: 정리, 원문 열기. 번역/원문 전환과 "AI에게 질문"은 제목 아래 줄에 둔다. 그 아래에 접을 수 있는 요약카드가 온다. → [번역과 요약](./translation.md) 데스크톱은 같은 액션을 상단 바와 우측 280px 정리 열(lg 이상)에 둔다.
- 파트가 2개 이상이면 상단에 고정된 **인덱스 바**(본문 · 이어쓰기 N · 인용 · 맥락)를 보여준다. 누르면 해당 파트로 이동하고, 스크롤 위치에 따라 현재 파트가 강조된다(IntersectionObserver).
- 본문은 배경 위에 그대로 두고, 이어쓰기·인용·맥락은 **카드**로 분리한다. 카드 머리에 원문 버튼(맥락 제외)과 접기 버튼을 둔다.
- 600자를 넘는 비본문 파트는 접힌 상태로 시작하고 "전체 펼치기"로 연다. 본문은 접지 않는다.
- 상태 배지는 정상(`ok`)이 아닐 때만 보여준다. 언어 코드, 상대 시간 중복, "미디어 N · 파트 N", 파서 버전·스냅샷 수 같은 보존 정보는 화면에서 뺐다.

### 이미지 뷰어

- 모바일: 검정 배경에 이미지를 화면 폭에 꽉 채우고, 카운터와 닫기만 남긴다. 확대는 핀치·두 번 탭, 넘기기는 스와이프로 한다.
- 데스크톱: 확대 버튼, 이전/다음, 썸네일 줄, 안내 문구를 유지한다.
- 모바일 규칙은 Goodcase 원본을 고치지 않고 `bridge.css`의 미디어 쿼리로 덮는다.

## 시트와 제스처

`src/components/goodcase/overlays/dialog.tsx`가 모든 시트·대화상자를 담당한다.

- 진입·퇴장 애니메이션과 배경 페이드. 모바일 시트는 아래에서, 데스크톱 드로어는 오른쪽에서 슬라이드하고, 닫을 때도 애니메이션이 끝난 뒤 사라진다.
- 모바일 시트는 손잡이가 있고 끌어내려 닫는다(`useSheetDrag`). 시트 높이의 30%(최대 140px)를 넘기거나 빠르게 튕기면 닫히고, 아니면 제자리로 돌아간다. 손잡이·머리 영역, 또는 본문이 맨 위일 때만 끌기가 시작되고 입력창에서는 시작하지 않는다. iOS 네이티브 스크롤이 가로채지 않도록 터치 이동을 직접 잡는다.
- 이미지 뷰어는 모바일에서 1배일 때 아래로 쓸어 닫는다(`use-viewer-gesture.ts`). 처음 움직인 방향으로 좌우 스와이프·핀치와 구분한다.
- 칩 누름 피드백, 토스트 옆으로 밀어 닫기.
- `prefers-reduced-motion`이면 모션 없이 열고 닫는다.
- 시트를 닫으면 포커스가 연 버튼으로 돌아간다(이전에는 페이지 맨 앞으로 빠졌다).
- 모바일 판정 너비 767px가 `dialog.tsx`와 `bridge.css` 두 곳에 있다. 한쪽을 바꾸면 다른 쪽도 맞춘다.
- 시트 끌기·이미지 뷰어 쓸어 닫기·클립보드 말풍선·노치 영역은 실기기 검증을 마쳤다(2026-10-26 사용자 확인).

## 숨김

- 상세의 정리 패널 맨 아래 "이 글 숨기기" 행(시트·데스크톱 우측 열 공통). 확인 없이 숨기고 목록으로 `router.back()`, 토스트에 "되돌리기". 숨긴 글을 열면 상단에 안내가 뜨고 같은 자리가 "숨김 해제"로 바뀐다.
- 필터 시트의 "숨긴 글만 보기"를 켜면 개수 옆에 `숨긴 글 ×` 칩이 뜬다. 카드에는 별도 배지가 없다.
- 목록과 검색에서 숨긴 글은 빠진다. → [결정 016](../decisions/016-hide-posts.md)

## 검색 카드 배지와 뒤로가기

- 의미 검색으로만 걸린 카드에는 "내용이 비슷" 또는 "이미지와 비슷" 배지가 붙는다. `?debug=1`이면 배지에 유사도 수치도 붙는다. → [결정 014](../decisions/014-semantic-search-embedder-sidecar.md)
- SNS·연결 자료 상세의 `BackLink`는 이전 목록으로 돌아가 검색어·필터·페이지·보기 방식을 유지한다. 연결 자료 상세의 `/` 고정 링크를 제거했다(2026-10-28). 지원 브라우저에서는 `navigation.canGoBack`으로 같은 출처의 이전 기록을 확인하고, 미지원 브라우저는 기존 `history.length` 판단을 사용한다. 기본 링크는 `/`이며 Ctrl/Cmd·Shift·보조 클릭은 가로채지 않는다.
- `staleTimes.dynamic: 30` 때문에 상태를 바꾸고 돌아간 목록이 옛 캐시로 보일 수 있다. 상태를 바꾸는 동작은 서버 액션 + `revalidatePath`로 캐시를 비운다(숨김이 첫 사례). → [결정 016](../decisions/016-hide-posts.md)

## 타이포

Pretendard Variable 하나를 `src/app/fonts/`에 두고 `next/font/local`로 서빙한다. 2MB 파일 하나라 첫 방문에만 받고 이후에는 캐시를 쓴다. 모바일 데이터에서 첫 화면이 느리면 Pretendard의 dynamic subset으로 바꾼다.

| 크기 | 용도 |
|---|---|
| 24px bold | 화면 제목 |
| 20px | 게시글 제목(모바일) |
| 16px / 1.7 | 게시글 본문, 모든 입력창(16px 미만이면 iOS가 포커스 때 화면을 확대한다) |
| 14px | UI 기본: 버튼, 칩, 목록 제목, 카드 본문 |
| 12px | 라벨·메타(`.label`): 작성자, 날짜, 건수, 섹션 이름 |
| 11px | 최소값. 배지 숫자에만 |

이 밖의 크기는 쓰지 않는다. Goodcase 토큰도 `--gc-text-sm 12 · base 14 · lg 20 · title 24`로 맞췄다. `html`의 font-size는 16px로 고정해 Tailwind rem 간격이 흔들리지 않게 한다.

### CSS 우선순위 함정 (입력창 14px 사건)

`text-[16px]`를 줬는데도 검색창이 14px이었다. 원인은 **레이어 밖(unlayered) CSS가 Tailwind v4의 레이어 CSS를 항상 이긴다**는 점이다.

- Tailwind 유틸리티는 `@layer utilities` 안에 있다. 그런데 `globals.css`가 가져오는 `global.css`·`basic.css`·`bridge.css` 등 Goodcase 이식 CSS는 레이어가 없다.
- `global.css`의 `input, textarea, select { font: inherit }`는 선택자 우선순위가 낮아도 레이어 밖이라 `text-[16px]`를 이기고, 입력창이 body의 14px을 상속했다. `.gc-input`은 클래스 선택자라 bridge의 16px이 적용되고 있었다.
- 같은 이유로 `button { font: inherit }`는 버튼의 `text-[16px]`를, `img { max-width: 100% }`는 `max-w-[260px]`·`mx-auto`를 조용히 덮어쓰고 있다. 클래스 이름만 보고 값을 믿지 말고 **computed style로 확인한다.**
- 조치(2026-10-26 적용): `global.css`를 `@import "../styles/global.css" layer(base);`로 가져와 base 레이어에 넣고, 입력창 16px 규칙도 `global.css`로 옮겼다(`bridge.css`의 규칙은 삭제). 이제 유틸리티가 리셋 기본값을 항상 이긴다.
- 적용 전후로 6개 화면 1145개 요소의 computed style을 비교하니 차이는 세 곳이었다: `/add` 붙여넣기 버튼 14px→16px(`text-[16px]` 의도대로), 상세 메모 textarea 줄 높이 24→26px, 도움말 캡처 이미지 폭 303→260px(`max-w-[260px]` 의도대로, 페이지 높이 약 560px 감소). 도움말 이미지 축소는 사용자가 승인했다.
- Goodcase CSS 전체를 `layer(components)`로 옮기는 안은 `.gc-*`가 유틸리티에 지게 되어 영향 범위가 넓어 보류했다.

## Goodcase 이식

`src/components/goodcase/`에 Button, Badge, Card, TextField, Drawer, Toast, ImageViewer, Spinner, Skeleton 등을 두고, `src/styles/bridge.css`에서 `--gc-*` 토큰을 앱 팔레트에 연결했다.

동작 계약은 유지한다: 포커스 트랩, Escape 닫기, 중복 실행 차단, 실패 시 입력 유지, 이미지 뷰어의 확대·스와이프.

이식하면서 확인한 문제:

- 아이콘 전용 버튼에 접근 가능한 이름이 없어 자동화가 버튼을 찾지 못했다. `aria-label`을 추가했다.
- `bridge.css`의 `.gc-modal` 배경 규칙이 이미지 뷰어 다이얼로그에도 걸려, 뷰어 배경이 검정 대신 표면색으로 나왔다. `.gc-modal:not(.gc-viewer-dialog)`로 제외했다.
- Goodcase 토스트의 stack 레이아웃은 원래 먼저 온 알림을 앞에 두어, 연달아 알림이 오면 새 알림이 이전 알림 뒤에 숨었다. 오프라인 대기열 전송 결과가 가려지는 문제가 생겨서 새 알림이 앞에 오도록 `toast.tsx`의 `notify`를 고쳤다.

## 색상

## 검증

- 2026-10-25 개편 후 390×844과 1280에서 라이브러리(그리드·목록), 검색, 수집, 상세(본문·이어쓰기 이동), 이미지 뷰어를 확인했다.
- 2026-10-25 시트·뷰어 제스처를 Playwright 터치 흉내로 390×844에서 확인했다(필터·정리·직접 입력 시트, 이미지 뷰어, 동작 줄이기). 실기기 감각은 미검증.
- 붙여넣고 저장은 클립보드를 대체 함수로 바꿔 세 경우(링크 없음, 지원하지 않는 링크, 읽기 거부)를 확인했다. 실제 iOS 클립보드 동작, 노치·홈 인디케이터 영역, 핀치·스와이프는 실기기에서 검증하지 않았다.
- `/api/ingest`의 거절 응답(전부 거절 400, 일부 거절 200 + `rejected`, 빈 입력 400)을 실제 요청으로 확인했다.


## 통합 라이브러리 드롭다운 (2026-10-28)

선택형 드롭다운은 `src/components/goodcase/overlays/select.tsx`의 Radix 기반 공용 `Select`를 사용한다. 라이브러리 필터 6곳(저장 위치·출처·컬렉션·형식·정렬·태그)과 저장소별 자동 새로고침 1곳에 적용했다. 앱 코드의 네이티브 `<select>`는 `pnpm lint:ui`에서 거절하며 공용 primitive 내부는 검사 대상에서 제외한다.

공용 컴포넌트는 외부 값 `""`을 “전체” 선택으로 받을 수 있다. Radix가 빈 항목 값을 예약하므로 내부에서만 모든 값을 인코딩하고 변경 콜백에는 원래 값을 전달한다. 값이 비어 있고 전체 항목이 없을 때의 placeholder 동작도 유지한다. `isDisabled`와 외부 레이아웃용 `className`을 사용한다.

Goodcase의 레이어 밖 기본 토큰이 밝은 배경·파란 강조색을 되살리는 문제는 `bridge.css`에서 `.gc-select`와 포털의 `.gc-floating`에 박제 색상을 지정해 해결했다. 드롭다운 트리거 높이는 44px이고 메뉴는 기존 공용 항목·스크롤·선택 표시를 사용한다.

실제 브라우저에서 키보드 선택, 전체 초기화에 따른 URL 제거, Space로 열기, Escape로 닫기·포커스 복귀, 390px 모바일의 경계 안 배치, 저장 요청 중 disabled, 자동 새로고침의 숫자 변환을 확인했다. 설정 저장 검증은 로컬 요청을 모의 처리해 운영 설정을 바꾸지 않았다. 캡처는 `/tmp/bakje-select/desktop-open.png`, `/tmp/bakje-select/mobile-open.png`다.


### 연결 자료 상세의 목록 복귀 수정 (2026-10-28)

`/items/[id]`에서 “라이브러리”가 고정 `/` 링크였기 때문에 검색 결과에서 상세를 열고 누르면 조건이 사라졌다. SNS 상세와 같은 공용 `BackLink`를 사용하고 화면에는 “목록으로”를 표시한다. 추가 전역 상태나 검색값 저장소를 만들지 않고 목록 URL과 브라우저 방문 기록을 그대로 사용한다.

로컬 프로덕션 빌드에서 검색어 `logo`, 출처, 저장소, 목록 보기, 2페이지가 복원되는 것을 확인했다. 상세 새로고침 후 복귀, 브라우저 뒤로가기, `/search?q=logo` 복귀도 통과했다. 직접 진입 시 `history.length=2`여도 이전 항목이 빈 페이지이면 지원 브라우저에서 기본 목록으로 이동한다. Navigation API의 같은 출처 기록 판단은 [HTML 표준](https://html.spec.whatwg.org/multipage/nav-history-apis.html#dom-navigation-cangoback)을 참고했다. 미지원 브라우저의 직접 진입 예외는 기존 판단을 유지하며 iPhone 실기기 검증은 하지 않았다.

검증 화면은 `/tmp/bakje-backlink/restored-list.png`다.


### 묶음 편집과 원본 정리 화면 (2026-10-28)

자료 상세에 접는 **자료 묶음 편집**과 **원본 폴더 정리**를 추가했다. 역할 선택은 공용 Select, 구성요소 선택은 Checkbox, 순서 변경은 IconButton, 분리·합치기·원본 이동 확인은 Dialog를 사용한다. `/library`의 저장소에도 전체 원본 정리 패널이 있다. 실제 적용은 파일 경로와 크기를 미리 보고 확인창의 체크박스를 선택한 뒤 실행한다. 원본 정리 완료·실패·되돌림을 폴링하면 상세 경로와 묶음 편집 잠금을 갱신한다.

새 확인창의 어두운 배경에서 글자가 어둡게 보였던 문제는 `.gc-modal:not(.gc-viewer-dialog)`에 앱의 글자·표면·테두리 토큰을 지정해 해결했다. 이미지 뷰어의 전용 토큰은 유지한다.
