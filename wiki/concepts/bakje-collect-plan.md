# 박제 수집 스킬 통합 계획

이 문서는 수집 통합 방향과 구현 범위를 정리한다. 2026-11-03 부분 수정 MCP와 수집 스킬 통합을 구현하고 로컬 검증했다. 2026-11-03 운영 배포와 기존 UX 사례·초안 규칙 전체 이전을 완료했다. 원본 저장소는 보존했다.

## 배경과 목표

박제를 개인 통합 지식 저장소로 사용하면서 코드와 UX 사례를 별도 저장소·절차로 관리할 필요가 줄었다. 현재 `bakje-code`는 코드 검색과 등록을 다루고, `ux-collect`와 `ux-solve`는 별도의 UX 저장소와 CLI를 사용한다. UX 저장소의 사례·규칙·출처·자료 분리와 검증 절차는 개인 수집에는 부담이 될 수 있다.

목표는 자료를 다시 찾고 사용할 수 있을 만큼만 정리하는 것이다. 별도 범용 스킬을 추가하기보다 `bakje-code`를 `bakje-collect`로 확장해 박제 수집의 진입점으로 사용한다.

## 제안 구조

```text
bakje-collect/
├── SKILL.md
└── references/
    ├── code.md
    └── ux.md
```

`SKILL.md`는 적용 범위, 박제 검색과 수집의 공통 절차, 자료 유형별 지침 선택을 담는다. 필요한 참조 파일만 읽는다. 일반 문서와 아이디어는 공통 절차로 다루고, 반복되는 필요가 확인되면 유형별 지침을 추가한다.

### 공통 절차

1. 독립적으로 찾아 활용할 수 있는 단위로 자료를 묶는다.
2. 박제에서 기존 항목을 확인한다. 같은 자료는 보완하고 다른 자료는 별도로 등록한다.
3. 무엇인지, 언제 참고할지, 출처와 확인된 내용을 기록한다. 개인 메모처럼 출처가 없거나 정보가 미확인인 경우 억지로 채우지 않는다.
4. 필요한 원문·코드·이미지·영상 등을 구성요소로 연결한다. 저장 위치와 실제 지원 형식은 등록 전에 확인한다.
5. 등록 결과와 경고를 확인하고, 다시 찾을 법한 표현으로 검색한다. 확인하지 못한 점을 함께 보고한다.

수집 경로와 저장 위치에 따라 실제 MCP 도구와 제약을 확인한다. 연결 폴더의 원본은 박제가 직접 쓰지 않으며, 연결이나 운영 설정 변경은 기존 권한과 절차를 따른다.

### 코드 지침

기존 `bakje-code`의 코드 등록 지침을 `references/code.md`로 옮긴다. 문제와 사용 상황, 진입점과 파일 역할, 연결 방법, 의존성과 버전, 실행 충실도와 검증 범위를 설명한다. 이해에 필요한 파일 구조를 유지한다. 코드 항목의 `fidelity`, `durability`, `depends_on`, `verified_at`과 profile 기준은 기존 동작과 호환되게 보존한다. 코드 검색과 신선도 판단 지침도 잃지 않도록 공통 진입점과 코드 지침의 위치를 정한다.

### UX 지침

하나의 독립적인 UX 문제 또는 사례를 박제 항목 하나로 정리한다. 상황과 문제, 확인 가능한 근거, 시도와 확인된 결과, 다음에 참고할 조건을 자료가 허용하는 만큼 기록한다. 해결 전 문제만 있어도 수집할 수 있다. 같은 문제의 후속 결과는 기존 항목에 보완한다.

규칙·출처·자료를 각각 별도 엔터티로 만들거나 공개 상태·해시·검증 체계를 모든 사례에 강제하지 않는다. 반복된 사례에서 실제로 재사용할 만한 원칙이 생기면 별도 지식으로 정리한다. 관찰과 해석, 제안과 실제 검증 결과는 구분한다.

## 다른 스킬과 기존 자료

- `ux-collect`: 박제 기반 수집이 필요한 흐름을 충족하면 독립 스킬 제거를 검토한다. 제거 전 호출처와 기존 자료 접근 방법을 확인한다.
- `ux-solve`: 현재 화면·코드 조사, 개선과 검증이라는 역할이 별도로 유용한지 검토한다. 유지한다면 전용 저장소 의존을 박제 검색과 수집으로 바꾸고, 독립적인 지침이 부족하면 제거를 검토한다. 존폐는 아직 확정하지 않았다.
- 기존 UX 저장소: 자동 삭제하거나 일괄 이전하지 않는다. 자료의 위치와 내용, 보존할 사례를 확인한 뒤 박제 표현과 이전 범위를 정한다. 원본을 유지하면서 대표 사례로 검색과 갱신을 검증한다.

## 작업 순서

1. 현재 스킬과 MCP 안내, 프로젝트 문서 및 다른 설치 위치에서 `bakje-code`·`ux-collect`·`ux-solve` 참조와 실제 사용 경로를 조사한다.
2. `bakje-collect` 공통 절차와 코드·UX 참조 지침을 작성한다. 기존 코드 검색·등록 계약과 저장소 제약을 보존한다.
3. MCP 힌트·경고·문서 등 확인된 이름 참조를 갱신하고, 기존 호출과 설치 경로에 필요한 호환 방식을 정한다.
4. 코드, 해결 전 UX 문제, 해결 결과가 있는 UX 사례, 일반 자료를 각각 예시로 점검한다. 중복 확인·등록·검색·기존 항목 갱신과 원자료 접근 가능 여부를 확인한다. 실행할 수 없는 항목은 미검증으로 남긴다.
5. 기존 UX 자료의 표본과 전환 방식을 검토하고, `ux-collect` 및 `ux-solve`의 유지·변경·제거를 결정한다. 실제 이전과 제거는 범위를 확인한 뒤 수행한다.
6. 관련 문서와 실제 변경 범위에 맞는 검증 결과를 기록한다.

## 완료 기준과 미결 사항

- 하나의 수집 진입점에서 코드·UX·일반 자료를 다룰 수 있고, 필요한 유형 지침만 읽는다.
- 기존 코드 항목의 검색·등록 및 신선도 판단 기준을 유지한다.
- UX 사례는 별도 DB 없이 문제만으로도 기록 가능하며 근거와 검증 수준을 구분한다.
- 기존 이름의 참조와 UX 자료의 보존·전환 방침이 확인되고, 실제 수행한 검증과 남은 한계가 기록된다.

확정: UX는 kind=ux, 기존 항목의 보완은 patch_library_item으로 처리한다. 기존 UX 사례와 초안 규칙 전체를 이전했다. 이후 사용자 지시에 따라 호환 스킬은 제거하고 bakje-collect 정본은 박제 저장소에 둔다.


## 구현 결과 (2026-11-03)

- 박제본→구성요소→파일 모델, DB 스키마와 기존 폴더 구조를 유지했다. 새 자료의 항목별 폴더·README·첨부 구성을 권장하고 item.json은 선택 사항으로 두었다.
- `.agents/skills/bakje-collect/SKILL.md`가 공통 검색·수집·수정을 안내하며 `references/code.md`와 `references/ux.md`를 필요할 때 읽는다. 코드 profile v2와 신선도 계약을 유지한다. UX kind는 `ux`, 일반 문서는 `document`를 관례로 사용하며 새 enum을 강제하지 않는다.
- `patch_library_item`은 최신 revision을 받아 구성요소 key별 추가·교체와 명시적 삭제를 수행한다. 요청에 없는 구성요소·파일 참조·임베딩을 보존한다. 교체 구성요소는 kind·role·text/path를 완전히 전달하며 구성요소 metadata와 항목 metadata는 최상위 키를 병합한다. tags는 전달 시 교체한다. 임의 메타데이터 키 삭제 연산은 제공하지 않는다.
- 수정하지 않은 파일은 다시 읽지 않는다. 변경된 파일은 별도로 편집 후 해당 key/path를 제출해야 읽는다. MCP는 원본 파일에 쓰지 않는다. 카탈로그 수정과 호스트 파일 편집을 하나의 트랜잭션으로 묶지는 않는다.
- 텍스트 변경은 FTS에 반영하고 변경·삭제·임베딩 해제된 구성요소의 예전 벡터를 제거한다. 기존 분석 큐가 필요한 텍스트·이미지를 처리하고 변경 없는 벡터는 재사용한다. 제목·태그·메모는 키워드 색인 대상이며 구성요소 임베딩 입력에는 포함되지 않는다. 상세 MCP와 부분 수정 응답에서 현재 구성요소 분석 상태를 조회한다.
- 기존 register_library_items는 전체 교체 동작을 유지한다. 새 부분 수정은 SNS 원본, 비활성 저장소, 휴지통, 원본 정리 잠금, revision 충돌을 거부한다.
- 초기 통합에서는 bakje-code와 ux-collect에 호환 진입점을 두고 ux-solve는 박제 기반으로 전환했다. 이후 호환 진입점은 아래 최종 관리 방침에 따라 제거했다. 사용자 스킬 경로에는 bakje-collect를 연결하고 설치된 UX 스킬 진입점도 갱신했다. 기존 전용 UX 저장소·CLI·근거 파일은 보존했다.
- 검증: 임시 DB와 모의 임베딩 서버에서 코드·해결 전 UX·해결 기록·일반 문서의 등록/수정, 첨부 보존, 변경분 분석, FTS, 벡터 무효화, revision 충돌, 분석 도중 수정, 경로 제한, MCP 도구 목록/호출/충돌/인증 차단을 확인했다. 실제 모델 품질과 운영 서버 적용은 미검증이다.

초기 구현 시점에는 기존 UX 자료 이전과 운영 배포를 보류했다. 이후 사용자의 명시적 요청으로 아래 운영 배포·이전을 완료했다. 이후 호환 진입점을 제거했다. 웹의 구성요소 내용 편집 UI는 추가하지 않았다.


## 운영 배포·기존 UX 자료 이전 완료

릴리스 `20261103T044207Z`로 웹을 배포했다. 기존 embedder·사용자·볼륨·네트워크·재시작 정책을 유지했으며 새 `/library/ux-notes`만 읽기 전용으로 추가했다. 기존 저장소의 쓰기 권한은 현행 운영 설정을 보존했다. DB 온라인 백업·무결성 검사 뒤 배포했고 운영 health와 상세 HTTP 200을 확인했다.

기존 `~/Documents/UX-Library`의 실제 사례 4건·초안 규칙 4건을 저장소 6에 등록했다. 근거 메타데이터 7건과 출처 1건, 해결 이력·상태·예외·공개 제한을 보존했다. macOS `._*`와 재생성 가능한 `.index`는 복제 대상에서 제외했다. 원본 파일 31개는 `~/Library/ux-notes/legacy`에 내용 변경 없이 복제했다. 원래 폴더·설정·스킬의 기존 CLI 자원은 삭제하지 않았다.

운영 박제본 ID는 19917~19924, 등록 작업은 7이다. 실제 모델 분석 작업 20개 완료·벡터 22개를 확인했다. 구성요소가 공유하는 파일을 포함해 파일 참조 22개의 HTTP 응답 해시를 검사했고, 한국어 검색과 실제 부분 수정에서 구성요소 ID·hash·metadata 보존을 확인했다. 이전 전 19,916건에서 19,924건으로 증가했으며 SNS 78건을 유지하고 DB quick_check가 ok였다. 이전은 과거 사례의 현재 UI·배포·효과를 새로 검증한 것이 아니다.

`~/dev/leonamin-skills`에 bakje-collect·bakje-code·ux-collect·ux-solve 및 README를 반영했다. 목록 탐색과 임시 프로젝트의 Codex 대상 4개 스킬 설치·참조 링크를 검증했다. ux-solve는 자체 박제 계약 문서를 포함해 단독 설치를 지원한다. Git 커밋·push는 수행하지 않았다.


## 최종 스킬 관리 위치 (2026-11-03)

사용자 요청으로 호환 스킬 bakje-code·ux-collect를 박제 저장소·leonamin-skills·사용자 설치 경로에서 제거했다.

- bakje-collect: 박제 저장소 `.agents/skills/bakje-collect`에서만 관리한다. leonamin-skills의 복제본을 제거하고 사용자 설치 경로는 박제 저장소를 가리키는 링크로 유지했다.
- ux-solve: leonamin-skills에서 관리한다. 박제 저장소의 중복본을 제거하고 사용자 설치 경로를 leonamin-skills 정본에 연결했다.
- 기존 UX 접근용 스크립트와 참조는 `~/.local/share/bakje/legacy-ux-tools`로 보존했다. 이 경로에는 SKILL.md를 두지 않아 폐기한 수집 스킬로 탐색되지 않는다. 이전한 자료와 원본 UX 저장소는 바꾸지 않았다.
- 두 저장소의 스킬 탐색, 박제 저장소에서 임시 프로젝트에 bakje-collect 설치, 참조 링크·README 목록·설치 경로를 검증했다. README에 실제 관리 위치를 반영했다.
