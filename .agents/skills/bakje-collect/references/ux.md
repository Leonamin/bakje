# UX 사례 작성

하나의 독립적인 문제 또는 사례를 kind=ux 박제본 하나로 기록한다. 상황·문제만 확인되어도 수집한다.

설명 문서(role=doc)에 상황과 사용자 과업, 관찰한 문제, 근거 위치, 시도한 개선, 확인된 결과, 다시 참고할 조건을 자료가 허용하는 만큼 적는다. 없는 항목을 억지로 채우지 않는다. 관찰과 해석, 제안과 실제 검증 결과를 구분한다. 로컬 구현·배포 확인·사용자 효과를 각각 구분한다.

이미지에는 kind=image와 role=screenshot 또는 result, 영상에는 kind=video를 쓴다. 각 근거가 어느 상태·시점·동작을 보여주는지 설명한다. 비교 단계가 다른 이미지를 전후 증거로 제시하지 않는다. 생성 이미지를 실제 캡처로 쓰지 않는다. APNG의 전체 동작을 박제가 분석한다고 가정하지 않는다.

같은 사례의 해결 내용은 기존 설명을 수정하거나 날짜별 결과 문서·미디어를 추가한다. patch_library_item으로 변경할 key만 보내며 기존 근거는 보존한다. 규칙·출처·자료별 엔터티, 공개 상태, 해시 체계를 필수로 만들지 않는다. 여러 사례에서 재사용할 원칙이 확인되면 별도 문서로 만들고 원래 사례 ID를 기록한다.

기존 UX 저장소는 자동 삭제·일괄 이전하지 않는다. 실제 이전 범위를 정한 뒤 사례 ID·근거 파일·출처·해결 이력을 보존해 표본을 먼저 등록하고 검색·수정·원자료 접근을 확인한다. 이전 전에는 기존 CLI·저장소를 읽기 위한 자원을 유지한다.
